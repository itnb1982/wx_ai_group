🔍 根因分析

位置：backend/app/services/trade_executor.py

问题：_get_decrypted_key(self, provider) 方法的 def 定义行丢失，其代码体（查询 DB 的 APIKey + 解密逻辑）被错误地嵌入了 _push_feed() 方法内部（第78-86行）。

触发路径：交易执行 execute_cycle → 开仓成功 → 调用 _push_feed() 写 AI 活动流 → 执行到残留代码中的 APIKey.provider == provider → provider 变量未定义 → NameError

实际影响：交易订单已正常成交并写入数据库（Step 4下单 + Step 5 DB写入 在 _push_feed 之前已提交），但 AI 活动流写入失败，前端「交易执行流」面板可能缺失这3笔交易的实时展示。

修复方案：

  1. 从 _push_feed 方法中删除第78-86行的残留代码
  2. 新增独立的 def _get_decrypted_key(self, provider: str) -> str: 方法，将残留代码移入其中
  3. 同时检查 _push_feed 调用处的异常处理是否应区分"日志写入失败"和"交易执行失败"

处理状态：记录待修复 — 属代码缺陷修复，超出监控值班员权限范围（监控只做巡检和紧急重启，不修改策略/风控/源码）。系统其余部分运行正常，无需紧急干预。
