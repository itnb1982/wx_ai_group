4. 生产环境 .venv 详解（bootstrap 自动做，这里讲原理）

为什么 .venv 不随项目拷贝：Windows 上 .venv\Scripts\python.exe 只是个转发器，真实标准库/DLL 在创建它的那台机器 Python 安装目录里（记录在 pyvenv.cfg 的 home= 字段）。直接拷到别的机器会找不到路径而失败。因此交付包只带源码，venv 由 bootstrap.bat 在目标机现场生成。

依赖三件套（backend/ 下）：

  • requirements.txt — 核心：fastapi/uvicorn/sqlalchemy/mt5/pydantic/jose/redis/celery…
  • requirements-ml.txt — 重型可选：torch==2.6.0(cu124) + transformers 5.x + chronos-forecasting + accelerate（约 2.5-3GB）
  • requirements-dev.txt / requirements-optional.txt — 开发/可选

解释器发现顺序（商业可移植靠它，见 start_all.bat 与 runtime_paths.find_python）：

WX_PYTHON 环境变量 → 项目 .venv → 项目 venv → PATH 中 python → py launcher

整目录拷到任意电脑都能跑，靠的就是这个"相对路径 + 运行时发现"，严禁硬编码盘符。

5. Moirai 独立 venv（★★ 最易踩坑，必读）

5.1 为什么必须独立、且必须是 Python 3.12

Moirai 依赖 uni2ts，其锁定 numpy~=1.26.0。

  • Python 3.13：numpy 1.26 没有预编译 wheel，只能源码编译 → 需要 MSVC 工具链 → 本机没有 → pip install 必失败（Unknown compiler(s) "cl"）。
  • Python 3.12：numpy 1.26 有 cp312 预编译 wheel，无需 MSVC，一行装好。

结论：用本机已装（或新装）的 Python 3.12.x 建一个完全独立的 venv：F:\WanxiangAI\models\moirai_venv_py312。它不污染生产 .venv。

5.2 一键安装（推荐）

用管理员 PowerShell：

cd F:\WanxiangAI\models
.\install_moirai_venv.ps1

脚本默认用 C:\Users\15588\AppData\Local\Programs\Python\Python312\python.exe 建 F:\WanxiangAI\models\moirai_venv_py312。若你的 3.12 装在别处，传参：

.\install_moirai_venv.ps1 -PyExe "D:\Python312\python.exe" -VenvDir "F:\WanxiangAI\models\moirai_venv_py312"

5.3 手动安装（等价命令）

7. 启动与守护（★★ 禁用 Git Bash）

7.1 启动

.\start_all.bat

supervisor.py 行为：

  • 每 5s 探一次 http://127.0.0.1:8080/api/health；
  • 连续 4 次失败（~20s）判定"无声假死"→ 强杀 uvicorn 子进程并重启；
  • 启动期宽限 STARTUP_GRACE=240s（覆盖数据库自愈预算），转入健康后才启用严格存活探测；
  • 单一实例守卫（mutex + PID 锁），防止重复拉起。

7.2 ★★ 致命陷阱：禁用 Git Bash / MSYS2 / Cygwin 启动后端

在 Git Bash / MSYS2 / Cygwin 终端里 import torch 会触发 0xC0000005 ACCESS_VIOLATION 段错误（exit 139 / 3221225477，try/except 抓不住），而同一解释器在原生 cmd / PowerShell 下完全正常。

后果：Chronos 探针误判"本地模型永久不可用"并写盘 backend/data/torch_probe_cache.json → 本地时序模型再也不加载。

若已中招：删除 backend/data/torch_probe_cache.json，用原生终端重启即可恢复。

7.3 重启后端的标准姿势

F:\WanxiangAI\.venv\Scripts\python.exe backend\restart_backend.py

它只杀 uvicorn 子进程，supervisor 会自动重新拉起（不杀 supervisor 本身）。

9. 常见问题与坑（按踩坑频率排序）

坑 1 — Git Bash 起后端 → torch 段错误（最致命）

症状：本地时序模型全部不可用、后端频繁异常。

原因：Git Bash / MSYS2 下 import torch 段错误（见第 7.2 节）。

解决：一律用原生 PowerShell / cmd / start_all.bat；若已写坏缓存，删 backend/data/torch_probe_cache.json 后用原生终端重启。

坑 2 — Moirai 装不上（用了 Python 3.13）

症状：pip install uni2ts 报 Unknown compiler(s) "cl" / MSVC 缺失。

原因：numpy 1.26 无 3.13 wheel。

解决：换 Python 3.12 建独立 venv（见第 5 节）。

坑 3 — 后端反复重启循环

复合根因（2026-08-09 已修复，记录在此供排障）：

  1. supervisor_uvicorn.log 膨胀到 200MB+ → IO/磁盘压力 → 已加 50MB×3 代轮转；
  2. Chronos 用 torch_dtype=torch.bfloat16 在 RTX 3060 Ti 上触发 mat1 Float != BFloat16 协同预测异常 → 已改 torch.float32；
  3. Moirai 子进程 180s 超时可能挂起拖垮 uvicorn 健康探测 → 已加 60s 子进程超时 + 75s 线程池隔离 + 参考服务刷新 300s。

排障顺序：先看 supervisor.log 有无"健康探测连续 4 次失败"；再看 supervisor_uvicorn.log 有无 mat1/dtype 报错；最后看日志体积。

坑 4 — 首次起不来 / 登不进

原因：.env 未生成（SECRET_KEY 为空后端拒绝启动）或数据库未建。

解决：确认跑过 bootstrap.bat 第 5 步 init_deployment.py（可重复执行，不覆盖已有数据）。

坑 5 — 前端白屏

原因：浏览器缓存了旧 index.html。

解决：后端 NoCacheHTMLMiddleware + deploy.py 给资源引用注入 ?v=<mtime> 已兜底；硬刷（Ctrl+F5）即可。

坑 6 — 参考面板某卡片"暂不可用"

原因：对应模型权重缺失或其 venv 未就绪。

影响：仅该卡片不可用，主交易链路不受影响（参考面板是观测，不进决策链）。
