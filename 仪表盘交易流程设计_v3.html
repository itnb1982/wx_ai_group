万象AI — 仪表盘「AI 交易大脑」设计 v3（客户视角版）

2026-08-02 v3 | 修订说明：v2 解决了"平庸/黑盒"问题（6 个招牌亮点）。但 v2 仍是产品说明书视角。本版按客户真实使用场景补齐 5 块刚需屏：①多账号从 1 个到 10+ 的扩展性 ②AI 工作过程必须前台可见（不是幕后）③可切换周期的行情图+全指标+趋势 ④每个账号的持仓/盈利/订单详情 ⑤星迈时区驱动的休市倒计时。<br><br>设计红线（贯穿全版）：多赚钱、提准确率、不拦截；AI 过程展示 = 信任的源头，不是装饰。

0. 客户屏总览（一句话）

万象AI 的仪表盘不是一个"看盘工具"，而是一块让客户亲眼看见 AI 在思考、在进化、在赚钱的透明大屏。1 个账号能用，10 个账号也井然有序；行情随便切周期；每个账号赚多少、亏多少、仓拿了多久，一目了然；休市了还会主动倒计时喊你回来。

2. 模块 A：弹性账户网格（需求 1 + 需求 4）

2.1 扩展性设计原则

账号数量与渲染解耦——这是需求 1 的核心。过去 v2 把"4 个账号"写死成表格行，客户有 1 个或 12 个都会崩。本版改为：

账号数据 = 后端返回 Account[] 数组（长度 = 实际账号数，1 ~ N）
前端渲染 = CSS Grid auto-fill（每卡固定宽度 280px）
  ├─ 1 个账号  → 单行一张卡，居中，不空旷
  ├─ 4 个账号  → 一行排满，与 v2 体验一致
  ├─ 10+ 账号  → 自动换行成多行；超宽时容器横向滚动，不挤压变形
  └─ 聚合条    → 顶部始终有"组合总览"（总余额/总权益/今日总盈利/历史总盈利），与账号数无关

关键工程约束：所有聚合（总余额、总盈利、今日/历史分桶）都在后端按 user_id 聚合 accounts[]，前端只负责画，绝不在前端写死 4。后续即使客户加到 50 个账号，改的只是后端查询上限，前端零改动。

2.2 单账号详情卡（需求 4 的完整字段）

每个账号卡 = 身份区 + 4 个核心指标 + 持仓/订单抽屉：

需求 4 字段 → 数据契约：

字段来源计算口径
当前持仓mt5_worker.get_positions 实时列表，每条含 open_time，持仓时长 = 当前服务器时间 − open_time（用星迈时区，避免本地时差导致"今日"算错）
今日盈利Trade 表聚合以服务器时间（星迈）当天 00:00 为起点，已平仓 net_profit 求和 + 当前浮盈
历史总盈利Trade 表聚合全部已平仓 net_profit 累计（含历史）
今日订单Trade 表服务器时间当天开仓的订单数（开+平分别计或合并，面板注明口径）
历史订单Trade 表全部订单数
⚠️ "今日"必须以服务器时间界定，不能用本机时间。星迈 GMT+2/+3(DST)，北京 GMT+8，差 5~6 小时——用本地时间算"今日"会把凌晨的欧洲盘交易算到昨天，客户看到的数字就对不上 MT5 终端。后端统一用 MT5 服务器时间做日切（见模块 D）。

3. 模块 B：AI 工作剧场（需求 2 — 前台化）

客户原话："不能让这些过程在幕后，要在前台展现出来，让客户看到就觉得高科技感满满。"

这是与平庸 bot 最大的分水岭。我们把 AI 的三条生命线全部搬上大屏，实时滚动，而不是只在日志里跑：

3.1 辩论擂台（实时思考可见）🟡

  • 双模型（DeepSeek 激进派 × 混元稳健派）当场互驳，Meta-Agent 裁决。
  • WebSocket 逐句推送 decide_verbose() 转录，前端左右气泡渲染（红方/蓝方），顶部裁决条，底部"共识度"环。
  • 客户感知："原来我的 AI 不是瞎下单，它真的在吵架、在找理由。"

3.2 进化时间线（实时成长可见）🔧

  • 每平一笔仓 → 复盘 AI 对不对 → 调整双模型权重。这条链路实时显示：
  [14:02] 突破行情误判 ×2 → DeepSeek 在突破场景权重 0.50→0.42
  [14:35] 震荡市混元占优 → 震荡权重 混元 0.65→0.72
  [15:10] OPRO 评分 +0.3 → 基线 EWMA 上移
  • 客户感知："我的 AI 不是雇来的，是养大的，每天都在变聪明。"

3.3 交易执行流（实时动作可见）🔧

  • 每一次下单/平仓/风控拦截，作为一条"事件流"从下往上滚动：
  ⚡ 14:36:02  开仓  XAUUSD BUY 0.04 @4033.2 (共识度87%·强信号·4账号联动)
  🛡 14:36:05  风控   点差18pt 通过 · DD 4.2% 通过
  ✅ 15:01:33  平仓  XAUUSD BUY +$86 (TP触发·AI方向正确)
  ⚠ 15:02:10  分歧   共识度降至 52% → 仅 Top2 账号出击
  • 客户感知："每一笔钱进出都有迹可循，风控不是摆设。"

技术底座（已具备，本版只接 UI）：debate_engine.decide_verbose()（待扩）、MetaAgent.adjudicate() 已输出 confidence+权重、Trade 表已存 AI 决策、mt5_service 事件总线。WebSocket 推送频率：辩论/执行流实时，进化时间线每笔平仓触发。

4.4 趋势判读条

基于"五周期 EMA 方向 + ADX 强度 + 宏观镜像"合成一句话趋势：

趋势判读：偏多共振（H1/H4 多头 + ADX>25 趋势可信 + DXY 未走强）
建议动作：强信号可满仓 · 弱分歧则降仓（见共识度）
趋势判读是给客户看的简化结论，不参与决策（AI 仍自主判断），避免把展示变成硬规则。

5. 模块 D：市场时钟 — 休市状态 + 开市倒计时（需求 5）

5.1 星迈时区（已调研确认，官方帮助中心）

时段服务器时区说明
标准时间（11月~次年3月）GMT+2冬令时
夏令时（3月~11月）GMT+3跟随美国 DST
  • 与 IC Markets "纽约收盘"时区一致；MetaTrader 平台显示时间即此服务器时间。
  • 外汇惯例交易时段：周日 22:00（服务器时间，GMT+2/+3） 开盘 → 周五 22:00 收盘；每日约 00:00~01:00 有短暂日切休市（具体以券商 symbol_info_session_trade 为准）。

5.2 倒计时计算方案（双保险，避免算错）

第一手（权威）：从 MT5 运行时直接读
  ├─ 服务器当前时间：mt5.symbol_info_tick(symbol).time（服务器时间，自动跟随 DST）
  └─ 当日交易时段：mt5.symbol_info_session_trade(symbol, weekday)
        → 返回该品种当天真实的 [开市, 休市] 区间（含日切、节假日，券商给的，最准）
  ⇒ 用真实时段算"距下次开/休市"倒计时

第二手（兜底）：星迈静态时区配置
  当 MT5 未连接/读不到时段时，使用 STARTRADER_TZ = GMT+2/+3(DST) 静态推算
  夏令时判断：美国 DST 区间（3月第二个周日 ~ 11月第一个周日）

展示形态：

🔴 休市中（周末）          或        🟢 交易中
距下周一开市 09:42:18                距今日休市 01:48:55
（服务器时间 周六 22:14 GMT+3）      （服务器时间 周五 21:11 GMT+3）
  • 顶部状态条常驻，颜色 + 倒计时双重提示。
  • 所有"今日/历史"日切（模块 A）与倒计时共用同一套服务器时间源，保证全屏时间口径一致。
