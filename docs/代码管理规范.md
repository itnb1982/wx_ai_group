# 万象Ai 代码管理规范

## 仓库信息

- **远程仓库**: `https://github.com/itnb1982/wx_ai_group`
- **分支策略**: 主分支 `master`
- **认证方式**: Personal Access Token (PAT)

## 代码提交规范

### 1. 提交频率
- **每次功能开发完成后必须提交**
- **每次 bug 修复后必须提交**
- **每次架构调整后立即提交**

### 2. 提交信息格式
```
<类型>: <简短描述>

- 类型: feat(新功能), fix(修复), refactor(重构), docs(文档), style(格式), test(测试), chore(维护)
- 描述: 清晰说明本次提交的目的
```

### 3. 示例
```bash
feat: 添加用户登录功能
fix: 修复购物车结算时的价格计算错误
refactor: 重构数据库连接模块以提升性能
docs: 更新 API 接口文档
```

## Git 操作流程

### 日常开发流程

```bash
# 1. 拉取最新代码
git pull origin master

# 2. 开发功能/修复 bug

# 3. 检查更改
git status
git diff

# 4. 暂存更改
git add .

# 5. 提交更改
git commit -m "类型: 描述"

# 6. 推送代码
git push origin master
```

### 使用自动化脚本

```bash
# 同步代码（每次运行前）
scripts/git_version_control.bat

# 快速同步
scripts/git_sync.bat
```

## 代码管理规范

### 1. 分支管理
- **主分支**: `master` - 始终保持可部署状态
- **开发分支**: 功能开发使用独立分支（可选）
- **禁止直接修改 master** - 除非是紧急修复

### 2. 文件管理
- **已提交文件**: 所有源代码、配置文件、文档
- **忽略文件**: 通过 `.gitignore` 管理
  - 大型文件（模型、数据）
  - 临时文件（日志、缓存）
  - 环境变量（密钥、配置）
  - 构建产物（node_modules, dist）

### 3. 版本控制
- **语义化版本**: `主版本.次版本.修订号`
  - 主版本: 不兼容的 API 修改
  - 次版本: 向后兼容的功能性新增
  - 修订号: 向后兼容的问题修正

## 自动化工作流

### 1. 运行前同步
- 每次运行项目前自动拉取最新代码
- 确保使用最新版本

### 2. 代码提交
- 开发完成后立即提交
- 保持提交信息清晰、有意义

### 3. 代码推送
- 本地测试通过后推送
- 确保远程仓库与本地一致

## 注意事项

### 1. 网络问题
- 推送代码需要 VPN 连接 GitHub
- 如遇网络问题，先检查 VPN 状态
- 可使用 SSH 方式替代 HTTPS（更稳定）

### 2. 冲突处理
- 如遇合并冲突，先拉取远程代码
- 手动解决冲突后提交
- 避免多人同时修改同一文件

### 3. 备份策略
- 远程仓库即为备份
- 定期拉取最新代码
- 重要版本可打标签（tag）
