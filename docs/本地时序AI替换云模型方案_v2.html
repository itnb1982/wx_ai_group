1. 必须纠正的误区（否则搭建走偏）

Chronos 不是 DeepSeek 的"同岗位替换"，是"不同工种"：

DeepSeek V4（被替换）Chronos-Bolt（替换者）
工种综合裁判价格预报员
输入SMC/Regime 等当前快照特征（文字）一段历史价格序列（数值）
输出BUY/SELL/HOLD + 置信 + 推理文本未来价格的分位数概率分布
能力多因素定性综合、解释时序建模、零-shot 预报未来

关键推论：删掉 DeepSeek 之后，原来"把多个定性因素揉成决策"的综合裁判层就空了。这层必须我们重新搭——这正是"搭建方案很重要"的核心工程。Chronos 解决"未来价格分布"，但解决不了"该不该进、进多少、为什么"，那部分要靠我们新建的决策合成层。

与"双模型辩论"的本质区别：原来用两个云 LLM 互相吵架来交叉验证；现在用 Chronos 两个周期（M15 短 + H1 长）的方向预报 + SMC 结构 做天然三方互验——价格时序维度 + 结构维度双保险，且全本地零费。

3. 各层职责与搭建要点

  1. 行情层（已就绪）：复用 mt5_worker.py 的 copy_rates_from_pos/copy_rates_range 取数，无需重写。
  2. 特征层（护城河·须先修偏置）：我们的 compute_smc / detect_regime 硬特征是独有优势。⚠️ 近期 BUY-only 巨亏（-$6,743）根因是 regime 把下跌错判上涨——在歪的方向上做预报只会精确向亏钱方向收敛，必须先修稳再上 Chronos。
  3. 预报层（Chronos base 205M）：本地 GPU 常驻（fp16 ~400MB-1GB 显存，3060 Ti 8GB 绰绰有余）。输入价格序列 → 输出分位分布。
  4. 决策合成层（新搭·成败关键）：把 Chronos 预报方向（如"未来 60min 80% 概率在 4230-4240"）+ SMC 结构确认（需求区/OB/FVG）+ Regime 体制（趋势/震荡）→ 规则化综合出信号与置信。这是本方案最该花工时的地方。
  5. 互验层：M15 + H1 两周期方向须同向（或至少一个强信号），且 SMC 结构不矛盾，才放行。
  6. 执行层（已落地）：L1 默认 SL/TP、L2 反转确认、L3 篮子护盾，保持不变。
  7. 可视化（升级）：把 Chronos 的概率分位云做成"预报动画"——你想要的"动画片而不是数字"，直接喂产品"AI 工作要被看见"的诉求。

5. 盈利闸门（守你的红线）

  • walk-forward 5 折训练在过去、测未来；必须覆盖 2020 新冠暴涨 / 2022 加息熊 / 2023 横盘 / 2024 牛市 四态，否则过拟合。

  • 低质信号处理：优先用仓位缩放（降手数）而非全拦截，保交易笔数（你"过度过滤砍利润"教训的延续；但红线已明确=赚钱不亏本，凡验证能提升净盈利的硬拦截也可用）。
  • 分布外风险：Chronos 是通用时间序列预训练（能源/销售/交通），未必对 XAU 高波动/跳空/三时段最优，必须用 XAU 历史数据实跑验证，不可盲信"预训练强"。

7. 风险与回退

  • Chronos 通用预训练，XAU 分布外 → 必须 P4 实跑验证；不过关则回退或降级 small 48M。
  • 8GB 显存约束：base 205M(~1GB fp16) + 系统余量 OK，但不能同跑本地 7B LLM（若要本地 LLM 裁判须另配卡或 CPU 卸载，本方案已不依赖）。
  • 决策合成层是新建 → 是成败关键，规则设计须保守、可回测。
  • 回退方案：保留 DeepSeek/Hunyuan 接口与 debate_engine 代码，验证不过关一键切回云模型，不损失现有能力。
