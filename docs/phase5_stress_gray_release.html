2. 压测方法论

2.1 为什么离线即可验

真正的多租户风险集中在三件事，且全部收敛在 app/core/account_lane 的纯函数 / 有界容器里，不依赖 MT5 实时行情：

风险点落点压测打法
同秒挤单（执行层错峰）apply_order_jitter / compute_jitter_ms直接驱动，断言抖动窗口
线程池膨胀LanePool（硬上界 32）N=50 并发打单，断言不死锁/不爆炸
滑点归因串号ConcurrencyAttribution（环形缓冲 cap=400）N 账号并发写，断言只挂自己 id

脚本导入的就是这些真实原语，不 mock 决策链，覆盖 N=1/4/10/50 × 每账号突发 K 单的组合。

2.2 四类 invariants（压测断言）

  1. 错峰窗口正确：N=1 零延迟（绝不无谓惩罚单客户）；N≥2 单次抖动均匀落在 [0, 800]ms，窗口下界 ≥200ms（高并发必打散），上界封顶 800ms（不随 N 无限增长）。
  2. 租户隔离：每账号的成交归因只挂自己的 account_id，绝不串号 / 串资金；无越界账号。
  3. 有界吞吐：有界车道池（硬上界 32）不会被 N=50 打爆；突发下单无死锁、无异常外抛（错峰=优化非闸门）。
  4. 内存有界：归因环形缓冲（deque maxlen=400）长跑不泄漏，常驻内存 <8MB。

2.3 运行方式

cd F:/WanxiangAI/backend
# 默认 N∈{1,4,10,50}，每账号突发 200 单
python scripts/stress_test.py
# 快速冒烟（N=1/4，每账号 20 单）
python scripts/stress_test.py --quick
# 指定规模
python scripts/stress_test.py --accounts 50 --orders 500 --seed 7

退出码 0 = 全部 invariants 通过；非 0 = 存在违反（末尾 FAIL 报告）。

⚠️ 实现注意：窗口正确性必须用纯计算 compute_jitter_ms（不 sleep）；apply_order_jitter 会真 sleep，放循环里会把测试挂成几十分钟。隔离测试用小批量（N×iso_k < 400）使全部账号落入缓冲，避免被 cap 丢弃早期样本导致误判。

4. 灰度发布（Canary）方案

4.1 客户独立性铁律（对应风险三层作用域）

作用域含义灰度含义
L-A 账号级一个交易账号 = 一个独立客户每个客户数据/策略/风控完全隔离，独立接入执行车道
L-B 风险域级同客户 1 主号 + 若干跟号仅这一组可合并算资金风险（继承主号风控参数）
L-C 平台级跨客户绝不合并客户资金；平台只熔断「信号源」，绝不熔断客户资金
红线：任何「跨客户合并资金风控 / 用 A 的亏损停 B 的单」提案 = 作废。系统性风险来自信号源相关性而非资金相关性。

4.2 发布阶段

阶段客户规模目标验收门槛（soak 3~5 个交易日）
阶段 0内部测试账号（liumanchun1~4，已就绪）demo 实盘验证全链路health NORMAL / 无熔断 / PF>1 / 无跨客户资金事件
阶段 1首批 1~5 真实客户验证单客户独立接入每客户独立风控生效 / 授权激活 / 无串号
阶段 25~20 客户验证有界池吞吐 + 滑点归因高并发档滑点不显著劣于低并发档（crowding_suspected=False）
阶段 320~50+ 客户全规模平台级无熔断 / 单客户异常不扩散

每阶段之间留 soak 窗口；任一客户触发日损熔断只影响其自身（L-A），不波及他人。

4.3 每客户接入检查清单

  1. mt5_accounts.user_id 正确注册（驱动后续策略/风控归属）。
  2. strategy_configs.user_id == mt5_accounts.user_id（否则双过滤匹配不到 → 全员回退默认 follow_leader=True，独立参数全失效）。
  3. 主号 + 跟号风险域（L-B）合并配置正确（跟号 follow_leader=1 继承主号 25 个风控/平仓字段）。
  4. 独立风控参数（SL/TP/手数/日损）按客户本金自适应。
  5. 客户端授权激活（Phase 8：Ed25519 + 机器指纹 + 心跳）；失效只停开新仓，绝不强平。

4.4 熔断与回滚

  • 平台级（L3）只关水龙头不抽水：信号源系统性风险（连败/模型不可用/行情断线/鞭锯超阈）→ 只停发新开仓信号，已有持仓交回各账号 SL/TP/SmartExit/护盾篮子，绝不强平。口诀「只关水龙头，不抽走桶里的水」。
  • 人工紧急处置（L-M）分级：E1 单仓 / E2 单账号 / E3 风险域 / E4 全体；halt_after 默认强制勾选（平完 AI 又开回来）。可单账号/单域/全体暂停，不影响其他客户。这是第四个授权来源（人），系统永不自动触发。
  • 单客户异常不扩散：账号级隔离 + 有界池，单客户崩溃只体现在该账号 ok=False（见 LanePool.map_accounts），不拖垮其他租户。

4.5 客户 Onboarding 自动化（目标流程）

新客户提供 MT5 账号+本金
   → DB 注册 mt5_accounts（user_id）
   → 策略配置继承（follow_leader + 独立参数）
   → 授权激活（Phase 8 客户端）
   → 自动接入执行车道（LanePool）/ 参与错峰
   → 监控面板按账号独立展示（AI剧场/质量陪审团/风控事件流/账户网格）
