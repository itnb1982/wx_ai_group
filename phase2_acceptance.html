二、本轮交付：Task #295 根治 torch 崩溃拖垮全系统

根因：venv 的 Python 被就地升级 3.13.12 → 3.13.14，torch 2.6.0 的 _C.cp313-win_amd64.pyd 按旧版编译，ABI 不匹配 → import torch 触发原生 access violation（0xC0000005 / 退出码 3221225477）。原 try/except 包裹 import 是「虚假降级保护」，抓不住原生段错误 → 整进程消失 → supervisor 误判假死 → 无限重启死循环（每 5s 崩一次）。

方案：子进程探针隔离——主进程永不裸 import torch，先 fork 短命子进程探测，把「进程级崩溃」转为「可捕获的子进程退出码」，按 (解释器+torch 二进制) 指纹缓存磁盘，超时不写盘、确定失败写盘永久降级；探针失败 → _ensure_loaded 永久降级，决策回退 SMC/Regime，系统照常交易。status 属性同步去除裸 __import__("torch")。

三、验证铁证（三重）

  1. 原生崩溃被隔离：venv 下真实 import torch 触发 0xC0000005，主进程存活（Exit 0）、ensure_loaded=False、优雅降级打印 torch 探针子进程崩溃 rc=3221225477 0xC0000005 ACCESS_VIOLATION。
  2. 测试：全量 1126+ 通过无回归；新增 tests/test_chronos_probe_isolation.py 19 用例全过（含反向守卫：静态校验"探针在 import torch 之前"、模块顶层无 import torch、status 无 __import__('torch')）。
  3. 端到端：supervisor 拉起后 /api/health 返回：

    即 Chronos 降级后决策自动回退 SMC/Regime，系统照常交易。
