# 万象Ai 持续验证器 — 执行记忆

## 采集要点（供后续轮次复用，避免重复摸索）

- **鉴权**：`/api/local-model/status` 与 `/api/dashboard/accounts` 需 Bearer token。
  先 POST `/api/auth/login`（body `{"email","password"}`）取 `access_token`。
  凭据与 `backend/audit_all_apis.py` 一致。`/api/health` 无需鉴权。
- **采集脚本**（已落盘，可直接复用）：
  - `backend/_verify_hourly.py` — 登录 + 拉三个接口，输出 JSON 到 stdout
  - `backend/_verify_db.py` — 只读 SQLite 统计（`file:...?mode=ro`）
- **活动数据库**：`F:/WanxiangAI/backend/data/wx_prod.dat`（`C:/WXDB/wx_prod.dat` 已过期，勿用）
- **trades 表列名陷阱**：无 `status` / `ticket` / `entry_price` / `sl_price` 列。
  实际为 `mt5_ticket`/`action`/`open_price`/`close_price`/`sl`/`tp`/`profit`/`net_profit`/`result`。
  未平单判据 = `close_time IS NULL`。
- **统计口径铁律**：**必须用 `profit`，不能用 `net_profit`**（后者恒为 0，会算出全 0 假结果，首轮已踩坑）。
  同时须排除 `exit_reason='mt5_closed_external'` 的零值单，否则胜率/PF 被严重稀释。
- **市场行情接口**：`/api/market/quote`、`/api/dashboard/market`、`/api/market/snapshot` 均 404。
  行情快照改从 `/api/dashboard/accounts` 的持仓 current_price + 日志中的 Chronos/裁决行提取。
- **日志位置**：`backend/supervisor_uvicorn.log`（约 45MB，用 `tail -N | grep -a`）。
  关键字：`smart_exit`（动态止损）、`AI出场`（浮亏单评估）、`L3护盾`、`持仓全景`、`MetaAgent`。
- **中文正则陷阱（第2轮踩坑）**：Git Bash 下 `python -c "...中文正则..."` 永远匹配不到，
  中文会被 shell 编码破坏。必须写成 UTF-8 脚本文件，或只用 ASCII 锚点
  （`get_all_positions_rescanned` / `smart_exit:evaluate_position:217` / `meta_agent:adjudicate:951`）。
- **日志计数陷阱**：按模块名匹配会把 INFO 一起算进去。`debate_engine:decide` 共 5832 行
  但 ERROR 仅 14 行——必须按日志级别二次过滤，否则误报为「系统性行情故障」。
- **只读分析脚本**（已落盘，可直接复用）：
  - `backend/_verify_log.py` — 日志异常按小时计数 + **后端重启时间点追踪** + 锁利明细 + 现价推算
  - `backend/_verify_daily.py` — 按日绩效 + **按出场原因绩效**（归因主力）+ 今日按账号
  - `backend/_verify_gap.py` — smart_exit 评估缺口 / 重启标记 / 关键活动时间线（第3轮新增）
  - `backend/_verify_levels.py` — 关键模块 × 日志级别交叉表 + ERROR topN（第3轮新增）
- **级别过滤铁律（第3轮修复）**：`_verify_log.py` 曾把 `debate_engine:decide` 的 6291 条 INFO
  当成「行情为模拟数据→强制HOLD」虚报 3951 次。已加 `LEVEL_FILTER`。
  **凡按模块名匹配的"故障类"事件，必须叠加 WARNING/ERROR 级别过滤**，否则必然虚报。
- **冷启动瞬态陷阱**：uptime < 30s 时 `mt5_connected` 可能显示 2/4、云端 `ready=false/total_ok=0`。
  **不要据此判 P0**，须轮询 health 60~90s 确认是否自愈（第3轮已验证 30s 内回 4/4）。
- **进程计数器 vs 日志真相**：`/api/local-model/status` 的 calls_ok / roles.runs 都是**按进程**计数，
  重启即清零。判断模型是否真在干活必须查日志（`_apply_proofread`、`deepseek_client`）。
- **锁利跟踪效率算法**：SL锁定点数 ÷ 当前浮盈点数。第3轮实测大单仅 33%~46%，跟踪效率 37%（第4轮已升至 62%）。
- **accounts 缓存陷阱（第4轮）**：`/api/dashboard/accounts` 可能返回 `cache_age_sec≈412`（7分钟前快照），
  持仓数会比 DB 少一半。**必须重新登录强制拉一次**（第二次调用 cache_age 会降到 <1s）才是真实持仓。
  已落盘 `backend/_verify_pos.py`（内含凭据，直接跑即可输出持仓+锁利效率+硬损点）。
- **DB profit 不可信（第4轮铁证）**：`profit` 字段存在**单位错配**——部分 1.0 手大单把「价差点数」
  直接写进 profit，未乘合约乘数 100。检测法：`expected=(close-open)*volume*100`，比值 ≈0.01 即中招。
  **绩效真相只能用 API 的 `today_profit`（MT5 口径），DB 汇总只能当下限。**
- **只读脚本 `backend/_verify_r5.py`（第5轮新增，可复用）**：单位错配自动检测 + 今日按账号「DB原始vs修正」
  + Chronos 出场贡献 + 未平单 DB/实盘 SL-TP 漂移对比 + 扫描失败按小时。
- **TP 清零 bug 定位法（第5轮闭环）**：对比「发生过 SL 上移的单」与「SL 从未移动的单」的实盘 tp 字段。
  前者 tp 恒为 0.0，后者完好 → 证明是 SL 修改连带清空 TP，非随机。DB 的 sl/tp 是**开仓快照、永不更新**，
  必须用 `/api/dashboard/accounts` 实盘值对比，只看 DB 会漏掉此 bug。
- **扫描失败与重启强相关（第5轮证实）**：425 次失败全在重启密集期，稳定进程 89 分钟内 0 次。
  判断该 P1 时**必须按小时切片并对齐重启时间点**，否则会把历史累计值误读为「仍在恶化」。
- **特征填充率口径陷阱**：`_verify_db.py` 输出的是**全历史**（chronos_vote 2.3%），
  第4轮的 57.8% 是**今日口径**。两者都对，报告中须注明口径，否则看似自相矛盾。
- **`trade_stale` 是振荡态，不可单点采样定性（第6轮）**：判定式 `trade_stale = auto_running and cycle_gap > 180`
  （`app/main.py:491`）。恰好采样到 180s 超时瞬间就会读到 true/degraded，**60~120s 后自行回 ok**。
  必须用 `health` 轮询 2 分钟（20s 间隔）确认是否自愈，否则会把正常振荡误报为故障。
- **周期超时归因锚点（第6轮新增）**：ASCII 锚点 `_run_cycle_with_timeout`（超时强制放弃本轮）、
  `run_cycle_for_user`（单账号预处理异常）。**必须叠加 `| ERROR` 过滤**。
  超时典型形态 = 精确每 4 分钟一次（180s 跑满 + 60s 间隔），连续多轮即为死循环节奏。
- **三处持仓数据源必须交叉比对（第6轮铁律）**：API 缓存 / DB `close_time IS NULL` / 实盘强刷
  三者可同时给出 8 / 10 / 6 三个不同值。**只有重新登录后 `cache_age_sec < 30` 的那次才是真值**，
  报告持仓务必用强刷值，且应把三者差异本身作为 P1 记录（暴露平仓回写滞后）。
- **锁利事件为 0 ≠ 机制失效（第6轮）**：先看持仓是否有浮盈。全部浮亏时不触发锁利属**合理未触发**。
  同理，此时 TP 字段完好**不能证伪** TP 清零 bug（未进入触发路径），勿据此结案。
- **只读脚本（第6轮新增，可复用）**：`backend/_verify_r6.py`（评估间隔按小时趋势 + ERROR TOP 模块）、
  `backend/_verify_r6b.py`（超时原文/按小时 + 扫描失败按小时×账号 + 全部重启时间点）、
  `backend/_verify_r6c.py`（行情快照 Chronos/MetaAgent/ATR/regime + 强刷实盘 TP 对账）。
- **只读脚本（第7轮新增，可复用）**：`backend/_verify_r7.py`（最近1h平仓明细+单位错配自动标记 / 今日锁利全天口径 /
  DB未平vs实盘 / 开仓节奏按小时 / 今日特征填充率 / 裁决·合票·冲突锚点）、
  `backend/_verify_r7b.py`（重启窗口逐秒事件链 / 平仓动作锚点计数 / 现价推算 / TP天花板序列 / 评估时间戳全量）。
- **空仓不等于故障（第7轮）**：判空仓成因看两个锚点——`execute_trade`/`order_send` 为 0 而 `intent=open` 非 0
  → 说明是**置信度低于阈值的设计内拦截**，不是执行链路坏了。勿据此判 P0。
- **MetaAgent 置信度提取陷阱**：日志行含时间戳数字，正则 `(\d\.\d{2})` 会误抓。
  必须用 `[:：](\d\.\d{2})` 锚定冒号后，才拿到真实「置信度:0.38 权重 DS:0.50/HY:0.50」。
- **外部平仓盈亏倒推法（第7轮新增，重要）**：DB 的 `mt5_closed_external` 单 `close_price` 被填成 `open_price`、
  `profit=0`，真实盈亏不可从 DB 得到。**倒推式**：本轮真实合计 = MT5 `today_profit` 增量 − 已知策略平仓盈亏和。
  第7轮实测 563.61 − 1302.31 = **−738.70**（18 笔外部单实为净亏，DB 记 0 等于抹掉亏损）。
- **重启→批量外部平仓因果链锚点**：`reconcile` WARNING 是批量标记动作的信号。
  形态 = 重启后 60~130s 内出现 reconcile 告警，同秒时间戳批量落多笔 `mt5_closed_external`。
  注意措辞：这些仓在 MT5 端**确已不存在**，系统只是"发现"，不能断言是重启把仓平了；问题在**盈亏未回写**。
- **`l3_tp_lock` 均单必须看手数分布**：全历史均单 679，但第7轮今日 31 笔均单仅 6.27——
  因今日全作用在 0.01/0.02 手小号跟单，大号通道未触发。**只看笔数会误判"锁利机制健康"**。
