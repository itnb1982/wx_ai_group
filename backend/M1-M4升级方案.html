二、设计哲学铁律（贯穿 M1~M4）

  1. 纯 AI 驱动：一切决策由 AI 模型，拒绝写死规则/方向门/多层过滤。
  2. 增删副号不影响 AI 进化：演化/记忆/lesson 只作用于主号（_is_leader=True）。
  3. 金融产品零延时：副号实时跟随（已有），M1~M4 不得引入副号侧 AI 推理。
  4. 验证红线：PF>1、不爆仓（单账号回撤≤15%）、交易笔数不腰斩、净利润不降；任一不满足即回退。

三、M1 — AI 出场 Agent（替换 smart_exit 规则）

3.1 为何现有机制错

  • smart_exit 是机械规则（move_atr≥TP 倍数 或 AI 反向阈值才动），无结构化离场意图；主号全平极少触发，利润捕捉靠分批阈值。
  • 框架已搭（ai_exit.evaluate 返回 {action, close_pct, new_sl, reason}），但被全局限速 + 缓存 TTL 逼回规则引擎，AI 几乎不生效。

3.2 海外最佳实践（≥3 源交叉验证）

  • ATLAS (arXiv:2510.15949, 2025-10)：Adaptive-OPRO + 多 Agent 协调；指出 GPT-o3 保守错失趋势、o4-mini 频繁止损早止盈；Reflection 机制引入噪声，强模型会过度分析瘫痪。→ M1 出场 Agent 须"有界"，禁止无限自省。
  • moondev RiskAgent (deepwiki, 2025)：AI 确认平仓前置（USE_AI_CONFIRMATION），组合价值监控间隔 5min，破限先 AI 分析再行动。→ 平仓侧接 AI 确认，保留硬护栏。
  • Tickeron Corridor Bots (2025-12)：固定走廊 TP/SL 自动化出场，情绪免疫、纪律一致。→ 印证"结构化离场意图"价值，但我们要 AI 动态而非固定。
  • Active Trader (2025-12)：1% 每笔风险 + 6% 月回撤刹车 + 最多 3 并发持仓。→ 平仓侧风控护栏参考。

3.3 XAUUSD 2026 出场特性

  • 黄金波动大（ATR 常态 $8-15/0.1 手），假突破频繁；出场须区分"健康回踩"与"趋势末端接飞刀"（沿用信号塔准确率方法论：价格距 MA 的 Z-score + RSI 极端 + 布林带破外轨）。
  • 分批止盈优于一次性：黄金趋势延续性强，过早全平损失趋势利润。
  • 反转出场需防抖（已有 L2 连续确认）。

3.4 机制设计

  • AI 出场 Agent 接管主号每持仓的离场决策，输出结构化动作：hold / partial_close(close_pct) / full_close / reverse_signal(→L2 防抖) / move_sl(new_sl)，附带 reason（人话，喂 M2 lesson + 前端可视化）。
  • 硬护栏保留：L2 反转防抖（reversal_confirm_cycles）、L3 篮子护盾（basket_tp）、风控 Layer1-6 在平仓前校验（平仓侧护栏）。
  • 提升 AI 覆盖率：放宽 ai_exit 限速为每账号独立锁（非全局），TTL 延长至 300s，后台并发评估；未命中缓存时降级为"保守默认"（移动 SL 保本位）而非 smart_exit 全规则。
  • 平仓侧风控护栏：full_close/reverse 前调 risk_engine 校验变体，禁止在回撤熔断时反手加仓。

四、M2 — Reflexion 捕捉率 lesson 管道

4.1 为何现有错

_EXIT_MFE 收集 MFE 仅入 payload，无 capture_rate=实盈/MFE 计算、无 lesson 存储 → 系统从错误中学习的能力为零。

4.2 海外最佳实践

  • Reflexion (arXiv:2303.11366, NeurIPS 2023)：Actor/Evaluator/Self-Reflection 三模块；verbal reinforcement learning；清晰评估器（binary feedback）才能 work（WebShop 模糊反馈失败）；记忆上限 1-3 条（长程需总结/索引，论文未解）。
  • 金融契合度：平仓盈亏 = 清晰二元/标量评估器，完美契合 Reflexion。
  • ATLAS 警告：Reflection 引入噪声，强模型过度分析瘫痪 → 反射须"有界"（限制反思长度 + 频率 + 只针对亏损/误判单）。

4.3 机制设计

  • Evaluator：每笔主号平仓算 capture_rate = 实盈 / MFE（MFE=该持仓历史最大浮盈）。capture_rate<0.3 或 亏损 = 失败信号。
  • Self-Reflection：对失败单，LLM 生成结构化 lesson：{错误类型, 根因, 改进动作, 适用场景}，存入 M3 episodic/semantic 记忆。
  • 有界反射：仅对亏损单 + 捕捉率异常单触发；每 N 笔平仓最多 1 次反思；lesson ≤200 字。

  • 验证：lesson 召回率、主号平仓 capture_rate 提升（回测对比）、不引入过度分析导致延迟。

五、M3 — FinMem 分层记忆

5.1 为何现有错

MetaAgent 权重零持久化（重启失忆）；ai_memory.py 仅环形缓冲，无分层。

5.2 海外最佳实践

  • FinMem (arXiv:2311.13743 → IEEE TBD 2025, 被引 228)：Profiling/Memory/Decision 三模块；Memory 分 working/episodic/semantic 三层，对齐人类交易员认知；可调认知跨度（cognitive span）。

5.3 机制设计

  • 三层记忆：
  • Working：当前周期上下文（持仓/行情/辩论摘要），容量 50 条，滚动。
  • Episodic：历史平仓事件 + lesson（来自 M2），容量 500 条，按 capture_rate/盈亏索引。
  • Semantic：提炼的"市场体制→最佳出场模式"规则（由 M2 lesson 聚类 + M4 演化产出），容量 100 条，长期。
  • 持久化：MetaAgent load/save_state 落 DB（deepseek_perf/hunyuan_perf/decision_history）；三层记忆落 SQLite/文件，重启恢复。
  • 认知跨度：可调，默认保留近 7 天。

层容量衰减持久化

  • 多账号：仅主号写记忆；跟号读主号镜像动作（不写）。

六、M4 — OPRO 演化循环

6.1 为何现有错

仅 EMA 权重，无"反思→改写 meta-prompt→再评估"循环。

6.2 海外最佳实践

  • OPRO (arXiv:2309.03409, Google DeepMind)：LLM as optimizer；meta-prompt 含历史解+分数，LLM 生成新解，评估后加入下一轮；GSM8K +8% / BBH +50%。
  • ATLAS Adaptive-OPRO：动态 prompt 优化 + 多 Agent 协调，更大模型优化响应强。
  • fitness 必须可量化：我们用"近期回测 PF + 捕捉率 + 不爆仓"。

6.3 机制设计

  • 演化目标（fitness）：主号近 7 天 PF>1.0 且 最大回撤≤15% 且 捕捉率≥0.5 → fitness = PF × 捕捉率 / (1+回撤)。
  • 演化对象：AI 出场 meta-prompt（deepseek_client.EXIT_DECISION_SYSTEM_PROMPT）+ 辩论裁决权重策略。
  • 循环：每 24h（或累积 N 笔平仓）触发；汇总 feedback 指标 → LLM 生成新 meta-prompt（top-8 候选）→ 回测评估 fitness → 接受最优（若 fitness>当前+ε）→ 写回常量/配置。
  • 回滚：新 prompt 导致 PF<1 或回撤>阈值 → 自动回滚上一版。

6.4 参数（全锁）

参数值
演化周期24h 或 累积 50 笔平仓
候选解数8
接受阈值 ε+0.02 fitness
回滚条件PF<1.0 或 回撤>15%
演化模型DeepSeek（信号量内，低频）
prompt 版本保留最近 10 版

6.5 接入点 / 验证

  • 接入：新增 _evolution_loop 守护线程（trading.py:255 附近）；改写 deepseek_client.EXIT_DECISION_SYSTEM_PROMPT（:25-50）。
  • 验证：演化后 PF↑、捕捉率↑、回撤受控；回滚机制可靠。

八、风险与回退

  1. 信号塔跨进程：若部署多 worker，需改 Redis/DB 共享总线（M1 前确认部署形态）。
  2. AI 出场延迟：后台评估 50s 超时 + 信号量，不得阻塞主周期。
  3. 过度反思（ATLAS 警告）：M2 严格有界，监控"反思调用频率"防瘫痪。
  4. 演化失控：M4 强制回滚 + 保留 10 版历史。
  5. 每模块回测达标（PF>1 / 不爆仓 / 交易数不腰斩 / 净利不降）才合并，否则回退。
