## 1. 目标

把 GPU1（RTX 3060 Ti 8GB）从 qwen2.5vl:3b（4.1GB 利用率 51%）升级到 qwen2.5vl:7b（约 5.4GB 权重 + KV + 图 tokens 约 6.5~7GB），让 H4/M15/M5 三周期结构识别在**开仓**和**平仓看护**两处都更准更智能。

铁律仍守：① 视觉仅加法增强，绝不做 GO/NO-GO 闸门（拦截=砍信号=利润腰斩）；② 与决策链同源 OHLC；③ 模型调用次数**不随账号数 N 线性增长**（信号跟随主号、跟单复制主号——见 §5）；④ 验收只看**净利↑、笔数不腰斩、PF>1**。

### 3.3 图表渲染升级（让 7b 看得更多）

**设计原则**：只画**客观价格结构**（任何图表软件都画得出的），绝不注入主观 SMC 结论（OB/FVG/流动性位留给模型自己判断）——守住既有"不替模型下结论"原则。

| 改动 | 旧 | 新 |
|---|---|---|
| `_MAX_EDGE`（最长边） | 672 | **784**（28 倍数；Qwen2.5-VL 动态分辨率原生支持；3 图视觉 token 仍在 4096 ctx 内） |
| 摆动高低点标注 | 无 | 新增 `_find_swings(bars, window=3)` fractal 算法 + `_swing_seq()` HH/HL/LH/LL 序列；图上画最近 12 个 swing 三角（H=橙/L=紫）+ 最近关键位虚线 + 右上角"上行结构/下行结构/震荡分歧"文字 |

### 3.4 vision_exit 去重铁律注释更正（无需改代码逻辑）

**关键发现**：代码现状其实已经符合铁律——`trade_executor._manage_positions` L3104-3106：
```python
if (not is_leader) and follow_leader:
    self._mirror_leader_exits(positions, ai_decision)
    return   # 跟单提前 return，根本到不了 _ensure_vision_exit()
```
跟单账号在镜像分支已 return，**只有主号/独立号才启动 VisionExitService**。

所以"去重"真实落点是**修正三处过时 docstring**，把架构事实写清楚，防止后人重犯"按账号数算调用"的错：

| 文件 | 改动 |
|---|---|
| `app/config.py` L213 | "每个 worker 进程(=一个账号)各自跑一个 VisionExitService" → "★铁律更正：跟单不启动本服务，只有主号/独立号推理，6/100 账号永远 ~1 次看护推理" |
| `app/services/vision_exit.py` 模块注释 | "每 worker 进程 = 一个账号" → "★★铁律：跟单不启动本服务" |
| `app/services/trade_executor.py` `_ensure_vision_exit` docstring | "每个账号(进程) 只设一次" → "仅在主号/独立号路径执行（跟单镜像分支已 return）" |

## 5. 模型调用次数铁律（用户 2026-08-16 纠正·已写入 MEMORY.md）

**信号跟随主号、跟单复制主号——视觉/AI 模型调用次数不随账号数 N 线性增长。**

- 跟单账号（follow_leader=True）在 `_manage_positions` 内走 `_mirror_leader_exits` 镜像主号出场即 return，**根本不启动 VisionExitService**。
- 主号的视觉看护票经 `publish_leader_exit` 广播给跟单，跟单直接消费。
- 所以无论 6 账号还是 100 账号，**永远只有 ~1 次看护推理**。
- 全局 vision_service（开仓结构识别）也是 1 个全局实例 + 1 次推理/刷新，与 N 无关。

评估任何模型升级/吞吐时，**调用次数由主号信号决定，与 N 无关**。
