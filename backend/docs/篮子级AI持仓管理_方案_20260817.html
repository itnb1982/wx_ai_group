AI 大脑盯盘持仓——篮子级 AI 持仓管理方案（PositionAction 协议）

2026-08-17 用户实盘观察触发：三单 SELL 合计最高浮盈 +10 美金，AI 无任何干预，<br>回吐至 0/亏损全程"智能平仓"静默。用户结论：智能平仓不智能——AI 大脑只管开仓，<br>不管持仓；持仓管理退化成逐单机械规则，没有篮子级联动视图。<br>本方案实现"AI 大脑盯盘持仓 + 篮子级处置"，纯加法、不砍交易。

一、问题根因（实盘证据）

#根因证据
AAI 大脑看到持仓但无法表达处置意见——输出协议只有 direction/confidence，没有"平/减/持"字段debate_engine 已注入 my_open_positions+portfolio_state（AI 看得见账本），但 JSON 输出 schema 无持仓处置项 → AI 只能"继续开/不开"，不能"我手里的单该平"
BL3 篮子锁利阈值过粗——basket_tp=30 美元，三单 +10 远未触发，回吐 20 全程无保护trade_executor L3154：basket_profit >= basket_th 纯静态阈值，无"峰值回吐"概念
C持仓管理逐单化——smart_exit/ai_exit M1 每笔独立评估，无"三单合计浮盈在回吐"的组合视图_manage_positions 对每笔 for pos in positions 独立跑规则
DAI 出场只判"反向"不判"动能衰竭/利润回吐"——ai_exit M1 只在 AI 置信反向≥0.6 时平，浮盈回吐靠规则 peak_move（单笔）单笔 peak_move 回吐≥30% 才有动作，三单合计回吐无篮子版

二、设计目标

  1. AI 大脑每次决策时主动评估当前全部持仓（篮子视角：方向/手数/浮盈/回吐/持有时长）
  2. 输出明确的持仓处置建议：hold（持有）/ trim（减半）/ close_all（全平）
  3. 行情不利时提前动作：浮盈回吐/结构破位 → AI 主动介入，不等机械阈值
  4. 铁律不变：提准非拦截（不砍开仓）、防抖防误杀（连续确认+置信门槛）、多赚钱（锁利）
  5. 跟单同步：处置结果复用现有 publish_leader_exit 广播（full_close/partial_close），跟号镜像消费

三、分层设计（L0→L4）

L0：AI 输出协议扩展（debate_engine + deepseek_client + hunyuan_client）

  • debate_engine prompt 增加指令：
  你有 N 笔持仓（见 my_open_positions），请基于行情与持仓浮盈/回吐情况，
  在 JSON 中输出 position_action 字段：
    {"action": "hold|trim|close_all", "confidence": 0~1, "reason": "简短理由"}
  hold=继续持有；trim=行情不利减仓一半；close_all=行情反转/风险高全平。
  没有持仓或判断不清 → action=hold。
  • JSON schema 扩展：position_action（缺失/非法 → 解析层回退 hold，零影响）
  • 解析兼容：deepseek _parse_response / hunyuan _safe_json_loads 提取 position_action 字段，任何异常回退 hold

L1：meta_agent 加权融合 + 防抖确认

  • 按现有 DS/HY 权重融合两票的 position_action：
  • 同向（都 close_all / 都 trim）→ 融合置信 = 加权均值
  • 分歧（DS trim + HY hold）→ 取更保守档（hold），置信 = max(两票置信) × 0.5（分歧降权）
  • 防抖确认：非 hold 动作需连续 2 轮（约 2 分钟）同向才可执行（篮子级确认状态，模块级 dict）
  • 置信门槛：BASKET_AI_MIN_CONF=0.60 才可执行
  • 输出：basket_action = {action, confidence, reason} 挂到 decision 对象

L2：执行层（trade_executor._manage_positions 主号路径）

  • close_all：逐笔平仓 + publish_leader_exit(full_close) 广播 + _record_close("篮子AI全平·回吐保护")；120s 冷却（同 L3）；部分失败不置冷却、下轮重试
  • trim：每笔平 50%（partial_close 广播，close_pct=0.5）；防碎单：若单笔 volume≤0.02 则不减（避免碎单）
  • 与 L3 共存：AI 处置是"提前量"（浮盈小/回吐早介入），L3 是规则兜底（浮盈大）
  • 位置：放在 L3 篮子护盾之前（AI 先判断，规则兜底）

L3：篮子回吐保护（规则补充——AI 不动作时的机械兜底）

  • 跟踪篮子浮盈峰值（模块级 dict _BASKET_PEAK_PNL[account]，每轮更新）
  • 触发条件：篮子浮盈 ≥ BASKET_PULLBACK_MIN_FLOOR(6美元) 且 从峰值回吐 ≥ BASKET_PULLBACK_PCT(50%) 或绝对值 ≥ BASKET_PULLBACK_ABS(8美元) → 全平锁利
  • 这正是用户案例的直接修法：三单 +10 → 回吐到 +5（回吐 50%）→ 触发全平，不会回吐到 0/亏损
  • 参数可配置（strategy_configs 继承主号）

L4：视觉看护修复（VisionExit 恢复后作为额外信号源）

  • 已加失败日志（重启后可见失败原因）
  • 恢复后其 full_close/partial_close 决策作为篮子处置的同向加分票（vision agree → 置信提升）

四、与现有层的关系（不破坏任何保护）

L1 硬 SL/TP（MT5 原生）      ── 不变
L2 smart_exit 规则（保本/追踪/分批/单笔回吐）── 不变
M1 AI 逐单出场（ai_exit 反向判）── 不变
L3 篮子护盾（浮盈≥阈值全平）  ── 不变
★ 新增：AI 篮子处置（PositionAction）── 在 L3 之前，AI 提前介入
★ 新增：篮子回吐保护（规则）  ── 在 L3 之前，峰值回吐即锁

七、验证方式

  1. 单测：position_action 解析（hold/trim/close_all/非法回退 hold）
  2. 单测：meta_agent 融合（DS trim+HY hold → 分歧降权不动作；DS+HY 都 close_all → 执行）
  3. 单测：篮子回吐触发（峰值 10 → 当前 4 → 触发全平；峰值 5 → 未达 floor 不触发）
  4. 实盘前向验证：下次三单合计浮盈 +10 后开始回吐，观察 AI 是否提前介入（预期 ≤2 轮确认内出 close_all/trim，回吐 50% 规则兜底）

八、风险与护栏

  • AI 抖动误杀 → 连续 2 轮确认 + 置信 0.6 + 120s 冷却，三重护栏
  • trim 碎单 → volume≤0.02 不减
  • 跟号一致性 → 复用现有广播机制，跟号镜像消费，不引入新通道
  • 解析失败 → 一律回退 hold，任何异常不影响现有决策链
  • 纯加法 → 不删除/修改现有 L1/L2/L3/M1 任何保护逻辑
