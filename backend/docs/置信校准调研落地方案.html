万象Ai 置信校准层 · 调研 + 落地方案

日期：2026-08-13　|　模块：app/core/confidence_calibrator.py + meta_agent 闸门接入　|　决策链：逆共识闸门 / 新闻闸门<br>铁律依据：提准非拦截（只让 0.80 真正表示 80% 命中，不改开仓笔数；默认不改手数）

一、背景与问题：为什么必须做置信校准

上一轮「统一大脑审计」发现一个硬伤（发现1）：逆共识高置信单胜率 51%，明显低于共识单 56%。而逆共识闸门的放行条件恰好是 final_confidence >= 0.80。

问题不在"逆共识"这个机制本身，而在 final_confidence 这个数值是虚高的：

  • meta_agent 把 DeepSeek / 混元 / Chronos 三脑的"自报置信度"按权重合并，但这个合并结果没有经过任何校准。
  • 文献与大量实证表明：LLM 集成输出的置信度系统性过自信——模型说 80%，真实命中率往往只有 ~60%。
  • 后果：逆共识闸门用虚高的 0.80 当阈值，会把一批"实际只有 50%~60% 命中"的弱逆共识单放进来，直接拖累信号准度。

所以"置信校准"不是给信号加一道新门（那是拦截，违背铁律），而是把阈值的语义还原成真实命中率——0.80 就真的表示 80% 会赢。该开的单照开，只是闸门判定的依据从"虚高自报"变成"历史观测命中率"。这是"提准"不是"拦截"。

二、全球调研依据（≥3 独立来源交叉验证）

2.1 LLM 输出系统性过自信（核心前提）

来源结论与本案关联
PredictEngine《Best Practices for LLM-Powered Trade Signals》LLM 给交易信号时"说 80% 实则命中 ~60%"是常态，需后校准直接对应本系统 final_confidence 虚高
dev.to / Polymarket 研究对真实市场事件，大模型校准曲线整体在对角线下方（过自信），Platt/Isotonic 可显著拉回印证"说得越满错得越多"
paperswithbacktest LoRA 去偏研究对金融决策 LLM，温度缩放 + Platt 把 ECE 从 0.18 降到 0.05 量级金融场景校准有效且必要

三家独立出处一致结论：LLM/集成置信度必须后校准，否则阈值判定失真。本项目 final_confidence 正属于此类。

2.2 校准方法学（文献一致结论）

方法原理适用本项目取舍
Platt Scaling逻辑回归 2 参数：σ(a·x + b)数据量小也稳、数据高效、单调本系统最终 Brier 选优落到它（见第五节）
Isotonic Regression (PAVA)保序回归，分段常数单调映射样本充足（>1000）时 ECE/Brier 优于 Platt2700+ 样本本应适用，但 auto 选优选了 Platt（更平滑、抗尾部稀疏）
Temperature Scaling单参数缩放 logits只移校准曲线、不动排序单参数表达力弱于 Platt，未采用
Conformal Prediction分布无关、频率覆盖保证需要校准带而非点估计输出"命中区间"而非"命中概率"，与闸门阈值语义不符，未采用

选型准则（行业共识）：在「时间切分」校准集上用 Brier Score 选优（Brier 同时惩罚校准与分辨力，比单纯 ECE 更适合选方法），全量 refit 后部署。金融数据非平稳，严禁随机切分（会前视泄漏），必须按时间切。

四、落地设计（严守铁律）

4.1 提准非拦截三原则

  1. 仅改阈值语义，不改开仓笔数：校准后 _calib_conf 替代 final_confidence 进闸门判定；降级（共识/逆共识）逻辑、交易数量完全不变。
  2. 默认不改手数：CONFIDENCE_CALIBRATION_AFFECTS_SIZING=False。校准只影响"准不准"，不影响"下多大"，守住"净利不降"及格线。日后若验证「按校准置信缩放手数」能提净利，再单独开调研落地。
  3. 运行期零侵入、零 DB 访问：离线拟合 → 写 data/confidence_calibration.json；meta_agent 运行期只 load() 这个 JSON 查表。JSON 缺失则透传（calibrated_conf == raw_conf），绝不阻塞交易。

4.2 数据流

生产库 trades（已平仓 2703 笔）
      │  scripts/calibrate_confidence.py 离线拟合
      ▼
data/confidence_calibration.json  （method=platt, params=[a,b], n=2703）
      │  meta_agent._get_calibrator() 运行期加载
      ▼
adjudicate：_calib_conf = calib.calibrate(final_confidence)
      │  → 新闻闸门 / 逆共识闸门 改用 _calib_conf 判定

DebateDecision.calibrated_confidence 落库 + 大脑审计 notes 追加"校准后置信 X%"

4.3 模块依赖隔离

confidence_calibrator.py 纯标准库（sqlite3/json/os/math/bisect），不依赖 MT5 / numpy / torch / sqlalchemy。校准拟合脚本用 importlib.util 直接加载该模块，绕过 app/__init__.py 的 SQLAlchemy 初始化，避免拖起整个后端。

十、结论

"置信校准"是上一轮审计发现1（逆共识单胜率偏低）的根因级修复：不是给信号加新门，而是把阈值语义从"虚高自报"校准成"真实命中率"。生产实证显示本系统 final_confidence 严重过自信（55%→16%、98%→67%），校准层用 Platt 映射把 0.80 阈值还原为真实 ~80% 命中，预期直接抬升逆共识单质量，且不改变交易笔数与默认手数——完全符合"提准非拦截"铁律与"交易笔数不腰斩 / 净利不降 / PF>1"及格线。

⚠️ 重要勘误（2026-08-13 15:45 追加·设计已修正）

原方案第七节"落点"把校准值直接喂进新闻/逆共识闸门阈值(0.80)——此设计经实测证明是致命缺陷，已修正为默认关闭。

致命缺陷证据

实跑拟合后发现：本系统 final_confidence 过自信极严重，校准后置信的天花板只有 0.79（raw=0.99→0.790；raw0.80→0.417 / 0.85→0.463 / 0.95→0.622）。要校准后≥0.80 需 raw≥0.990，超出可行域。

连锁后果（若按原方案部署）

  • 逆共识闸门 apply_contrarian_gate 在 conf<0.80 时把逆共识单降级为共识方向；因校准值全 <0.80 → 每一笔逆共识单都被无声改成共识方向。
  • 新闻窗口单 conf<0.80 全部 HOLD → 新闻窗口零成交。
  • = 彻底抹杀逆共识交易 + 新闻窗口零成交，直接撞"多交易多赚钱 / 提准非拦截"红线，且违反"拦截须 walk-forward 验证"铁律。

已修正（config.py + meta_agent.py）

  • 新增开关 CONFIDENCE_CALIBRATION_AFFECTS_GATES: bool = False（默认关）。
  • 闸门阈值默认仍用 raw final_confidence（零行为变化、保护交易笔数及格线）。
  • 校准值仅作诚实展示：DebateDecision.calibrated_confidence 字段 + 审计日志"校准后置信X%"，让运营/用户看到真实把握度。
  • 仅当 AFFECTS_GATES=True 且经 walk-forward 验证净盈利提升后才可开启（拦截须验证铁律）；AFFECTS_SIZING 同样默认关。

结论不变

"置信校准"的价值在于暴露并诚实化过自信（核心实证：55%→16%、98%→67%），而非收紧闸门。正确落点 = 诚实展示 + 可选仓位缩放（默认关），绝不做成变相拦截。本系统校准天花板<0.80 这一事实，本身已证明原"让 0.80 真正表示 80% 命中"的闸门化思路在当前信号质量下不可行。
